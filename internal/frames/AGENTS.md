# frames

Attributed, SDK-free frame admission and replay for SPEC-0002. The host owns persistence and producer policy; this package performs no I/O.
- Use one `Session` for all producers in a session; `NewLedger` creates an isolated session only. Each ledger has an immutable producer prefix, branch leaf and epoch. A source must equal its prefix or be a dotted child.
- Session admission keeps event-key receipts and all records, including superseded ones, for replay. Deduplication is per producer; reusing an event key with a different branch or epoch conflicts. Limit session pending frames to 256 and pending body bytes to 2 MiB; reject overflow without dropping records. History never blocks admission.
- Coalesce only pending info/notice records with matching producer, branch, epoch, source, subject and explicit key. Accepted but superseded records remain deduplicable.
- Session `Snapshot` records have a schema version and preserve provenance, payload, state and sequence. Restore complete session records atomically, without discarding or rewriting active records. The caller persists them under `pig-workbench.frame`.
- External publications retain their requested data trust for replay but receive conservative untrusted/data authority until host policy exists. A nonce is a provenance cue, not authentication; it is one value per `Session` (`SetNonce` lets the host restore the lineage value), never derived per frame.
- Delivery transitions live on the session: `SelectPending` returns the pending frames of one delivery mode for a branch leaf and epoch, `MarkDelivered` acknowledges the batch that entered an outgoing context, and `Cancel`/`Fail` retire pending frames. Selection alone never marks delivery. Stale branch or epoch scope reports `ErrStaleContext`; a transition on a non-pending frame reports `ErrInvalidTransition`, and a failed frame is retried by publishing again.
- Delivered, cancelled, expired and failed are terminal. They release the pending slot and pending body bytes but keep the record and its event-key receipt, so a later duplicate admission returns the original receipt and a restore never makes them pending again. Bodies of non-pending records are kept up to 2 MiB; beyond that the oldest lose their body (`bodyDropped`), keep digest and receipt, and are matched by digest. The host's persisted session entries still hold the text.
- Expiry uses the injected clock and is processed lazily on admission, selection and delivery acknowledgement; `Snapshot` serializes whatever state the session holds at that point. `Restore` accepts the terminal states, enforces the pending bounds only, and trims history to its bound, so records persisted with every body load.
- `EncodeEnvelope`/`DecodeEnvelope` preserve retained attribution, timestamp and nonce; delimiter escaping grants no authority. Host rendering and authority policy remain separate; acknowledgement is not provider receipt.
